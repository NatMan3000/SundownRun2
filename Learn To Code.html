Josh, the whole game is text

Sundown Run II was built for you. This page is where it starts being built by you. The road, the sun, the springs in the car, the Ai racers, the music: all of it is text in files. The browser reads the text, follows it like a recipe, and the world appears. Change the text and the world changes.

You have already done this. When you changed a value in config.ts and the game changed, that was programming. Everything on this page is more of that, one step further each chapter.

How this page works:

  • Every PLAYGROUND runs right here in the page. Change the code, press RUN (or Ctrl+Enter). Break it on purpose. Reset puts it back. You cannot hurt the game from here.
  • The pink pills like src/core/config.ts:29 open VS Code at that exact line of the real game. That is not example code, it is the code your game is running.
  • Each chapter ends with something to try in the real game. Keep the game running while you edit: it updates the moment you save.
If an experiment in the real files goes properly wrong, Ctrl+Z in VS Code undoes it, and Sundown Run II Update.bat is the big do-over button that puts the whole folder back. Nothing you try can break it for good.

Two ways to open this page: double-click Learn To Code.html in the game folder, or, while the game is running, go to http://localhost:5201/Learn To Code.html. When the code changes, bun run learn rebuilds this page so every link still points at the right line.

Chapter 1

The fun knobs

The simplest thing code can hold is a number. src/core/config.ts is a list of named numbers (programmers call them variables), and other code in the game reads them. power multiplies the engine's push. That is all a knob is: a name, a value, and some other line of code that uses it.

REAL GAME CODE src/core/config.ts:25
25// ---------- HANDLING ----------26grip: 1.0, //        0.7 = slippery drift machine ... 1.4 = glued to the road27steering: 1.0, //    steering sensitivity. 0.6 = calm and easy ... 1.5 = twitchy go-kart28stability: 1.0, //   how hard the car catches its own slides. 0.6 = loose ... 1.6 = very hard to spin29power: 1.0, //       engine power. 0.6 = grandma mode ... 1.6 = rocket mode30brakes: 1.0, //      0.6 = soft brakes ... 1.6 = stops on a coin31topSpeedKmh: 260, // the fastest the engine will push you (boost pads go past it!)

The // starts a comment: a note for humans that the computer skips. This game is full of them, written so you can read it.

Try it here. This drag race uses three of the real knobs, with their real values from your config.ts. The faded car is the default car, so you can see whether your change helped.

PLAYGROUND · Drag race

"Your edit wins"

The Settings menu can change most knobs while you play, and it remembers your choice. So what happens if you picked Power 1.2 in the menu last week, and today you type power: 1.4 into config.ts? The game saves each menu choice together with the config value it replaced. When it loads, it checks: is config.ts still the same as when you picked? If not, you changed the file on purpose, so the file wins.

REAL GAME CODE src/core/settings.ts:171
171function resolve(defaults: Settings): Settings {172  const out: Settings = { ...defaults, trackParams: { ...(saved.trackParams ?? {}) } }173  let pruned = false174  for (const key of Object.keys(defaults) as (keyof Settings)[]) {175    if (key === 'trackParams') continue176    const entry = saved[key]177    if (!entry) continue178    if (entry.d !== defaults[key] || typeof entry.v !== typeof defaults[key]) {179      delete saved[key] // config.ts changed since this was chosen: the edit wins180      pruned = true181      continue182    }183    ;(out as unknown as Record<string, unknown>)[key] = clampKey(key, entry.v as Settings[typeof key])184  }185  if (pruned) writeSaved(saved)186  return out187}

Line by line: for walks through every setting, if (entry.d !== defaults[key] ...) asks "is the config value different from when this was chosen?", and if it is, delete saved[key] throws the old menu choice away. Then the file hot-reloads through one place, so the game changes without a restart. The menu sliders also have limits, in SETTING_RANGES.

In the real game: open src/core/config.ts:29 and set power to 1.6. Save. Drive. Then find the fastest value that is still fun to drive. That's called tuning, and it is a real job.
Chapter 2

Colours are numbers too, and glow has a budget

'#ff2bd6' looks like a secret code, and it is a simple one. A colour is three numbers: how much red, green and blue light to mix, each from 0 to 255, written in hexadecimal (counting in 16s: 0-9 then a-f). ff = 255, 2b = 43, d6 = 214: lots of red, a little green, lots of blue. Magenta.

Every colour in the game lives in one file, palette.ts, so the whole world stays one look. Change a colour there and it changes everywhere.

REAL GAME CODE src/core/palette.ts:44
44// ---- road ----45road: '#0a0a12',46roadEdge: '#ff2bd6', //      default track accent (a track file may override)47roadEdgeAlt: '#19e3ff', //   secondary accent48laneLine: '#c4f7ff',49chevron: '#ffb000',50

Then there is glow. The bloom effect only lights up things brighter than 1.0, so every glowing thing picks a tier. If everything glowed at full power, nothing would stand out. The rule of the game: the brightest thing on screen is always the road, the car or the sun.

Chapter 3

Tracks are data, not code

Here's a big idea in programming: keep the data (what) apart from the code (how). A track in Sundown Run II is one file in the tracks/ folder, written in JSON, a format that is just lists [ ] and labelled values { }. The game's code reads the file and builds everything: the road, the hills, the jumps, the racing line the Ai follows, the minimap. Adding a track never touches code.

REAL GAME CODE tracks/neon-pocket.json:116
116"pieces": [117  {118    "type": "boost",119    "at": 0.75120  },121  {122    "type": "loop",123    "at": 2.0,

A road is a list of points (x is east, z is south, in metres) and the game runs a smooth curve through them. Pieces sit at an at: at: 2.0 means "at point 2", at: 0.75 means "three quarters of the way from point 0 to point 1".

This playground holds the real Neon Pocket. Move a point, add one, add a piece, press RUN to redraw. It uses the same kind of curve the game uses (a centripetal Catmull-Rom spline, from spline.ts).

Chapter 4

The game loop: 60 tiny steps a second

A game is a loop. Over and over: read the controls, move everything a tiny bit, draw the picture. Each pass through the loop is a step. The physics in Sundown Run II always takes exactly 60 steps a second, even if your screen draws 165 frames a second. That keeps the car behaving exactly the same on every computer.

REAL GAME CODE src/vehicle/tuning.ts:18
18export const DT = 1 / 60

But if the physics only moves 60 times a second and the screen draws 165 times, the car would look jerky. So the game interpolates: for each frame it draws the car part of the way between its last two physics positions. Smooth at any refresh rate.

After each step, the car writes everything it knows into one shared object called telemetry: speed, rpm, drifting, airborne. The HUD, camera, sound and effects all read it. No one asks the car; they just read the board.

REAL GAME CODE src/vehicle/PlayerCar.tsx:55

Chapter 5

The car floats on four invisible springs

Surprise: the car in Sundown Run II has no wheels in its physics. Each corner shoots a ray (an invisible laser) straight down. Where the ray hits the road, the game works out how squashed that corner's spring would be, and pushes the car up by that much. That's called raycast suspension, and real racing games do it.

REAL GAME CODE src/vehicle/carSim.ts:1275
1273const suspVel = prev >= 0 ? (toi - prev) / DT : _pointVel.dot(n) / Math.max(up.dot(n), 0.5)1274this.prevToi[i] = toi1275let f = k * this.compression[i] - (suspVel < 0 ? dC : dR) * suspVel1276let cap = fMax1277const bump = this.compression[i] - SUSPENSION.bumpStart1278if (bump > 0) {1279  f += SUSPENSION.bumpStiffness * massRatio * bump - (SUSPENSION.bumpDamp - 1) * (suspVel < 0 ? dC : dR) * suspVel1280  cap = fMax * SUSPENSION.bumpMaxScale1281}1282this.suspForce[i] = clamp(f, 0, cap) // a suspension pushes, never pulls

The important line is the lit-up one, let f = k * this.compression[i] - ...: the push is stiffness times how squashed (a spring), minus damping times how fast it's moving (a shock absorber, so it stops bouncing). That "how fast" is suspVel, two lines up: how much longer the ray got since the last step, divided by the step's time. Squash a spring nearly flat (past bumpStart) and a much stiffer bump stop joins in, the if (bump > 0) part, like the rubber block in a real car's suspension. And clamp(f, 0, cap) means a suspension can push but never pull.

REAL GAME CODE src/vehicle/tuning.ts:55
55export const SUSPENSION = {56  /** N/m per corner. Over a 300 kg quarter mass that is a 1.6 Hz ride, a real car's number. */57  stiffness: 30000,58  /** Rebound damps harder than compression, like a real damper: soak the bump, settle once. */59  dampCompress: 3600,60  dampRebound: 4600,61  /** Never launch the car into orbit off a kerb. */62  maxForce: 26000,

The playground drops one corner of the car using that same spring-and-damper formula (it leaves out the bump stop), 60 steps a second, with the game's real numbers.

Chapter 6

The road is a ribbon with a frame at every metre

Your track points go through a smooth curve (the spline), and then the game slices the curve every 1 metre. At each slice it stores a frame: which way is forward (the tangent), which way is up off the road surface, and which way is right. With those three arrows at every metre, it can build the road mesh, bank corners, flip you through loops, and tell the Ai where the edges are.

REAL GAME CODE src/track/types.ts:74
74export interface TrackFrame {75  s: number76  position: THREE.Vector377  tangent: THREE.Vector378  up: THREE.Vector379  right: THREE.Vector380  halfWidth: number81  bank: number82  curvature: number83  surface: SurfaceKind84}

Corners lean in (they're banked), so the car is pushed into the turn instead of sliding out. How much? The game uses the real physics formula: bank angle = atan(speed² / (gravity × radius)), capped so it's never steeper than the track allows.

When you land a trick, which code should play the sound, show the points and update the score? In this game, none of them know about each other. The trick code just announces it, once, on the event feed. Anything that cares listens. Chapter 8

The Ai driver: chase a dot up the road

An Ai racer drives the same car you do, with the same physics. It can't cheat; it just presses the same four controls. Its steering trick is called pure pursuit: pick a point a little way up the racing line, and steer toward it. The faster it goes, the further ahead it looks, which keeps it smooth.

REAL GAME CODE src/play/aiDriver.ts:156
155/** Aim point distance: base metres + metres per (m/s) of speed. */156const LOOK_BASE = 7157const LOOK_PER_MS = 0.55158const LOOK_MIN = 7159const LOOK_MAX = 75

Every physics step the brain finds its aim point and works out the angle to it. x is how far the dot is to the car's right, z is how far ahead, and Math.atan2(x, z) turns those two into an angle.

REAL GAME CODE src/play/aiDriver.ts:822
819_d.copy(_frame.right).multiplyScalar(this.laneNow).add(_frame.position).sub(p)820const x = _d.dot(_right)821const z = _d.dot(_fwd)822const alpha = Math.atan2(x, z) // + = aim point to my right823const alphaRate = clamp((alpha - this.prevAlpha) / dt, -8, 8)824this.prevAlpha = alpha

From an angle to a steering wheel

The simple way is "the bigger the angle, the harder you turn". The real brain is cleverer than that, in three ways:

  • It works out the curve. 2 * Math.sin(alpha) / chord is the exact circle that would carry the car through the dot (chord is how far away the dot is). That is the curve it wants.
  • It has a budget. clamp keeps that curve close to the road's own bend (kRoad): it may only add 4 m/s² of extra sideways push (about 0.4 g, CORRECTION_ALAT) to fix where it is, a bit more the further off its line it has got. Without a budget, being a few metres off line at 250 km/h would make it yank full lock and spin.
  • It learns its own steering. The same turn of the wheel bends the car far less at 200 km/h than at 50. So it divides by this.steerGain(v), its number for "how much the car turns per bit of steering at this speed", to turn the curve it wants into how much steering to use.
REAL GAME CODE src/play/aiDriver.ts:844
838const sMid = this.s + chord * 0.5839const kRoad = sampleAt(track, track.samples.curvature, sMid) * Math.cos(sampleAt(track, track.samples.bank, sMid))840// the further off line, the more we may spend getting back (a car 15 m off841// the road needs a real turn, not a polite nudge)842const offLine = Math.abs(this.hit.lateral - this.laneNow)843const kBudget = Math.min(CORRECTION_ALAT_MAX, CORRECTION_ALAT + CORRECTION_PER_M * offLine) / Math.max(25, speed * speed)844const kWanted = clamp((2 * Math.sin(alpha)) / chord, kRoad - kBudget, kRoad + kBudget)845const steerWanted = (kWanted / this.steerGain(v)) * PP_WEIGHT + STEER_DAMP * alphaRate846this.steer = clamp(steerWanted, -1, 1)

Where does that number come from? The brain learns it while it drives. It keeps one for each of four speeds (about 36, 97, 151 and 216 km/h), starting from numbers measured on the real car, STEER_GAIN_SEED. Each time it steers, it watches how much the car really turned (curv), works out what that says about its car (sample), and nudges the number for that speed 1 percent of the way toward it:

REAL GAME CODE src/play/aiDriver.ts:1068
1064const curv = -Math.asin(clamp(sinYaw, -1, 1)) / (v * dt)1065const sample = curv / this.steer1066if (Number.isFinite(sample) && sample > 0.002 && sample < 0.4) {1067  const b = this.bandOf(v)1068  this.steerGains[b] += (sample - this.steerGains[b]) * STEER_LEARN_RATE1069  // never wander far from the measured response (a long session must not drift)1070  this.steerGains[b] = clamp(this.steerGains[b], STEER_GAIN_SEED[b] * 0.6, STEER_GAIN_SEED[b] * 1.6)

The last line keeps every number between 0.6 and 1.6 times where it started, so a long race can't teach it anything silly. Learning a little at a time from what really happened, inside safe limits: that is the same idea real machine learning uses.

The HUD and the road editor

The speedometer never jumps. When you hit a boost pad, the number rolls up. That's one line of maths in the HUD: every frame, move the shown number a fraction of the way toward the real one.

PLAYGROUND · Speedo smoother
Try rate = 1 (lazy), rate = 60 (twitchy, nearly raw). The game uses 14 for speed and a slower 7 for the trick score. Why Math.exp? It makes the smoothing feel the same whether your screen draws 60 or 165 frames a second.

The editor lets you draw a track with a pencil instead of typing points. Your hand wobbles, so the editor runs your line through a clean-up pipeline, seven small functions in a row, each doing one job:

Quiz

Quick quiz

Six questions. No marks, no timer.

Last week you set Power to 1.2 in the Settings menu. Today you change power: 1.0 to power: 1.4 in config.ts and save. Which does the game use?
The file wins. The menu remembered that you chose 1.2 when config said 1.0. Config now says 1.4, so you changed it on purpose, and the old menu choice is dropped.
The skyline buildings far away need a glow tier. Which one?
T0: no bloom. Far-away things never out-glow the road, the car or the sun.
You add tracks/josh-1.json. Which code do you have to change for it to show up?
None. Tracks are data: drop the file in tracks/ and the game finds it.
Your screen draws 165 frames a second. How many physics steps does the car take each second?
60, always. The picture is interpolated between steps, which is why it still looks smooth at 165.
You want a sound every time someone lands a backflip. Where should your code go?
A listener on the event feed. The car just announces landings; it never needs to know your sound exists.
How many kicks in one bar of 'x---x---x---x---'?
4: one x on every beat. That's "four on the floor", the classic synthwave drive.
The real thing

Missions: edit the actual game, Josh

Everything above ran inside this page. These run in your real game. Start the game, keep it open next to VS Code, and click a pill to jump to the line. Save, and watch it change.

Mission 1 · Warm-up

Rocket mode

At src/core/config.ts:29 set power to 1.6, and at src/core/config.ts:31 set topSpeedKmh to 330. Drive. Is it still drivable? Can't stop in time for the corners any more? brakes at 1.6 "stops on a coin". Find your favourite mix.

Mission 2 · Chapter 2 skills

A paint job nobody else has

Build three colours by hand (pick red, green and blue numbers from 0 to 255 and turn each into two hex digits) and put them in paint, glow and trail. Rule from the art book: no pure primaries like #ff0000.

Mission 3 · Demolition

Everything smashes

At src/core/config.ts:60 set smashKmh to 10. Now almost any hit smashes roadside stuff. Then try boostStrength at 2.5 and take a boost pad into a crate cluster.

Mission 4 · Chapter 3 skills

Your first track

Sketch a track in the Chapter 3 playground, press Make track file, save it as tracks/josh-1.json, run bun run tracks:check tracks/josh-1.json, fix what it says, and drive it with ?track=josh-1. Then add a loop on your longest straight (read the pieces rules first: loops need four points in a line).

Mission 5 · Chapter 7 skills

Log every trick

In the game, F12, Console: __events.subscribe((e) => console.log(e.type, e)). Do a jump and open the trick.land event to see its tricks list. Then change a trick's name in tricks.ts ('TO THE MOON' is the biggest air) and see your name pop up in the HUD feed.

Mission 6 · Points economy

Spins are worth more

At SPIN_HALF_PTS every half spin is worth 100 points (a loop is 400). Make spins worth what you think they should be, then play Stunt mode: ?mode=stunt.

Mission 7 · Chapter 8 skills

Retune the Ai brain

At LOOK_BASE try the look-ahead that worked best in your Ai lab. Then at CORRECTION_ALAT, the brain's "how hard may I swerve back to my line" budget, try half of it (2) and double it (8). Race them on Neon Pocket. Did they get faster, or did they start crashing? Put the old numbers back if they got worse: that's how real tuning works. Leave STEER_GAIN_SEED alone: those were measured on the real car, and the brain tunes them itself as it drives (learnSteering).

Mission 8 · Chapter 9 skills

Your beat in the game

Copy your favourite kick pattern from the beat machine into the kick list of the drive mood at score.ts. Afterglow Valley and Neon Pocket each say their mood in their track file ("music": { "mood": ... }), so change that too if you want your beat everywhere.

Boss level

A new loop grip

At src/core/config.ts:61 the car sticks to loops and wall rides above magGripKmh. Set it to 30 and crawl round a loop. Set it to 160 and find out which loops you can still make. Then put your own track's loop in exactly the right spot with a boost pad 120 m before it. If you finish this one, you have changed data, physics, sound and the Ai. That's a game developer, Josh.

Keep this handy

Running your game

In the game folder, double-click:

Play

Sundown Run II.bat read it

Starts the game at http://localhost:5201. The first run installs what it needs; after that it starts in seconds. While it runs, every file you save updates the game.

Multiplayer

Sundown Run II Multiplayer.bat read it

Only one computer runs this: the host. It prints a link everyone else opens. Friends need nothing installed.

Do-over

Sundown Run II Update.bat read it

Gets the newest version and makes the folder an exact fresh copy. It throws away your changes, that's its job. Your best laps survive: they live in the browser, not the folder.

Found a bug?

Report a problem read it

On the title screen, or the pause menu while you drive, pick Report a problem. Say what kind it is (something's broken, an idea, something else), give it a title, say what happened, and Send. It goes to Dad on the game's GitHub page, with game details attached (See what gets sent shows every one). That page is public, so a first name or nickname only, never anything private. The game's own server sends it: server/issues.ts.

Commands (in a terminal in the game folder): bun run dev plays, bun run tracks:check checks every track, bun run learn rebuilds this page.
